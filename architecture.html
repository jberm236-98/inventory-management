Key invariant: useFilters state is declared outside the exported function, making it a module-level singleton. Every view shares the exact same four ref objects — no prop drilling, no Vuex/Pinia. When a filter changes, any view that calls getCurrentFilters() inside a watch or computed automatically re-fetches.

API Endpoints

Method Path Filter params Description
GET /api/inventory warehousecategory All inventory items

GET /api/orders warehousecategorystatusmonth Orders — month supports YYYY-MM or Q1-2025
GET /api/dashboard/summary all four Aggregated KPI totals
GET /api/demand — Demand forecasts (no filter)
GET /api/backlog — Backlog items + purchase-order flag
GET /api/spending/summary — Spend totals
GET /api/spending/monthly — Month-by-month spend
GET /api/spending/categories — Spend by category
GET /api/spending/transactions — Recent transactions
GET /api/reports/quarterly — Quarterly aggregates computed from orders
GET /api/reports/monthly-trends — Month-over-month order trends
GET /api/purchase-orders/{backlogItemId} — PO linked to a backlog item
POST /api/purchase-orders — Create purchase order (in-memory only)

Reactivity Pattern

Raw State (refs)

Hold data exactly as returned by the API — mutated on fetch.

Derived State (computed)

Computed properties that derive display data from refs — never mutated directly.
